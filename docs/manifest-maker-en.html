Manifest Maker – User Guide

Publishing a new image for Raspberry Flash · ManifestMaker 1.0

Manifest Maker creates the manifest.json file that tells Raspberry Flash which image is current. Upload it to the server next to the image, and every Raspberry Flash using that server picks up the new image the next time someone presses Flash.

This guide is for whoever maintains the images on the server. For writing SD cards, see the Raspberry Flash guide.

1. Requirements

  • Windows 10 or Windows 11. No administrator rights and no installation needed: just run ManifestMaker.exe.
  • The image file on your PC – the same file you upload to the server.
  • A web server folder reachable over http:// or https:// where you can upload files (FTP, web panel, cloud storage with public links…).

If the server supports partial downloads (HTTP Range requests, as almost all web servers do), Raspberry Flash can resume interrupted downloads of large images.

2. How it works

The server folder holds the image and manifest.json:

https://drive.example.com/
├── manifest.json
├── solaria231026.img      ← previous image (optional)
└── solaria151126.img      ← current image

Raspberry Flash reads manifest.json, finds the name of the current image, and downloads it unless a file with that same name is already in its local cache. Publishing a new image therefore means: upload the image under a new name, then replace manifest.json.

3. Publishing a new image

  1. Give the image a new file name, e.g. solaria151126.img. Including a date or version number in the name is the easiest way to keep names unique.

    Raspberry Flash recognises images by file name only. If you upload a changed image under a name that was already used, PCs that have that name in their cache keep writing the old copy.

  2. Upload the image to the server folder and wait for the upload to finish completely.

    Upload the image before the manifest. This way nobody is ever sent to an image that is not there yet. With FTP, use binary transfer mode.

  3. Start ManifestMaker.exe and press Browse... to select the same image on your PC.
  4. Check Version. It is filled in from the last group of digits in the file name (solaria151126.img → 151126). Change it if needed.
  5. Keep “Include SHA-256 checksum” ticked. Raspberry Flash then checks every download and rejects corrupted files.
  6. Press Create manifest. A save dialog opens in the image's folder, with the name manifest.json already filled in. Press Save.
    If the checksum is enabled, the progress bar shows how far the calculation has got; this takes a little while for large images. Cancel stops it.
  7. When the message “Manifest saved … Upload it next to …” appears, upload manifest.json to the same server folder, replacing the old one.

That's it: from the next press of Flash, every Raspberry Flash using that base URL downloads the new image.

4. The Manifest Maker window

ItemWhat it does
Image file + Browse...The image to publish. Accepted types: .img, .xz, .gz, .bz2, .zip (choose All files in the dialog to see others).
VersionA free label, filled in automatically from the file name. Raspberry Flash shows it in its log (Available version: …); it does not decide what is downloaded.
Include SHA-256 checksumAdds a fingerprint of the file to the manifest so that damaged downloads are detected. Recommended.
Progress bar and status lineShow the checksum calculation and the result.
Create manifest / CancelCreate and save manifest.json; stop a calculation in progress.

5. The manifest file

Manifest Maker writes a small text file like this:

{
  "version": "151126",
  "image": "solaria151126.img",
  "sha256": "3f5a…"
}
FieldMeaning
versionLabel shown to the user. Optional.
imageName of the image in the same folder as the manifest. Required. It can also be edited by hand into a full URL (https://…) if the image lives in another folder or on another server.
sha256Checksum of the image file exactly as uploaded. Optional; if present, Raspberry Flash rejects downloads that do not match.

Compressed images (e.g. .img.xz) download faster and are decompressed by Raspberry Flash while writing. The checksum is of the compressed file – just select the file you upload.

6. Checking the publication

  1. Open the base URL followed by manifest.json in a browser (e.g. https://drive.example.com/manifest.json): you should see the new contents. If you still see the old one, the browser or server may be caching it – reload after a moment.
  2. Start Raspberry Flash with that base URL and press Flash: the log shows Available version: … with the new name, followed by Downloading ….

7. Troubleshooting

Message / problemCause and solution
Please select an image file. (Manifest Maker)No file was chosen, or it was moved. Press Browse... again.
Raspberry Flash: Cannot read manifest.json: HTTP 404manifest.json is not in the folder of the base URL, or the file name is different (it must be exactly manifest.json, lower case).
Raspberry Flash: manifest.json is not valid JSON / has no "image" entryThe file was edited by hand incorrectly or truncated during upload. Create it again with Manifest Maker.
Raspberry Flash: Download failed: HTTP 404The image named in the manifest is not on the server, or its name differs (check upper/lower case). Upload it, or recreate the manifest from the file actually uploaded.
Raspberry Flash: Downloaded image is corrupted (checksum mismatch) on every PCThe manifest was made from a different file than the one on the server, or the upload was damaged (e.g. FTP in text mode). Upload the image again and recreate the manifest from that same file.
PCs keep writing the old imageThe new image was uploaded with a name that was already used. Rename it, upload it, and recreate the manifest.

8. FAQ

How do I go back to an earlier image?
Keep the previous image on the server. To roll back, create a manifest for it with Manifest Maker and upload it. PCs that still have it in their cache will not even need to download it again.
Can I delete old images from the server?
Yes, once they are no longer named in the manifest. Keeping the previous one makes a rollback quick.
Can I serve several products from one server?
Yes – use a separate folder, each with its own image and manifest.json. Each folder is a different base URL in Raspberry Flash.
Is the checksum required?
No, but without it a damaged download is only noticed when the Raspberry Pi fails to start.
