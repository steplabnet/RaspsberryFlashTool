Manifest Maker – Guida utente

Pubblicare una nuova immagine per Raspberry Flash · ManifestMaker 1.0

Manifest Maker crea il file manifest.json che indica a Raspberry Flash qual è l'immagine corrente. Caricatelo sul server accanto all'immagine: ogni Raspberry Flash che usa quel server userà la nuova immagine alla successiva pressione di Flash.

Questa guida è per chi gestisce le immagini sul server. Per scrivere le schede SD vedere la guida di Raspberry Flash.

L'interfaccia del programma è in inglese. In questa guida i nomi di pulsanti e campi sono riportati come appaiono sullo schermo, in grassetto.

1. Requisiti

  • Windows 10 o Windows 11. Non servono diritti di amministratore né installazione: basta avviare ManifestMaker.exe.
  • Il file immagine sul vostro PC – lo stesso file che caricate sul server.
  • Una cartella su un server web raggiungibile via http:// o https:// in cui poter caricare file (FTP, pannello web, cloud con link pubblici…).

Se il server supporta i download parziali (richieste HTTP Range, come quasi tutti i server web), Raspberry Flash può riprendere i download interrotti delle immagini grandi.

2. Come funziona

La cartella sul server contiene l'immagine e manifest.json:

https://drive.example.com/
├── manifest.json
├── solaria231026.img      ← immagine precedente (facoltativa)
└── solaria151126.img      ← immagine corrente

Raspberry Flash legge manifest.json, trova il nome dell'immagine corrente e la scarica, a meno che nella sua cache locale non ci sia già un file con lo stesso nome. Pubblicare una nuova immagine significa quindi: caricare l'immagine con un nome nuovo, poi sostituire manifest.json.

3. Pubblicare una nuova immagine

  1. Date all'immagine un nuovo nome di file, ad es. solaria151126.img. Inserire una data o un numero di versione nel nome è il modo più semplice per avere nomi sempre diversi.

    Raspberry Flash riconosce le immagini solo dal nome del file. Se caricate un'immagine modificata con un nome già usato, i PC che hanno quel nome nella cache continuano a scrivere la copia vecchia.

  2. Caricate l'immagine nella cartella del server e attendete che il caricamento sia completato.

    Caricate l'immagine prima del manifest: così nessuno viene mai indirizzato a un'immagine che non c'è ancora. Con l'FTP usate la modalità di trasferimento binaria.

  3. Avviate ManifestMaker.exe e premete Browse... per selezionare la stessa immagine sul vostro PC.
  4. Controllate Version. Viene compilato con l'ultimo gruppo di cifre del nome del file (solaria151126.img → 151126). Modificatelo se necessario.
  5. Lasciate attivo “Include SHA-256 checksum”. Raspberry Flash controllerà così ogni download e scarterà i file danneggiati.
  6. Premete Create manifest. Si apre la finestra di salvataggio nella cartella dell'immagine, con il nome manifest.json già inserito. Premete Salva.
    Se il checksum è attivo, la barra mostra l'avanzamento del calcolo, che per le immagini grandi richiede un po' di tempo. Cancel lo interrompe.
  7. Quando compare il messaggio “Manifest saved … Upload it next to …” (manifest salvato, caricatelo accanto a …), caricate manifest.json nella stessa cartella del server, sostituendo quello precedente.

Fatto: dalla successiva pressione di Flash, ogni Raspberry Flash che usa quell'indirizzo base scaricherà la nuova immagine.

4. La finestra di Manifest Maker

ElementoFunzione
Image file + Browse...L'immagine da pubblicare. Tipi accettati: .img, .xz, .gz, .bz2, .zip (scegliete All files nella finestra per vederne altri).
VersionUn'etichetta libera, compilata automaticamente dal nome del file. Raspberry Flash la mostra nel registro (Available version: …); non decide cosa viene scaricato.
Include SHA-256 checksumAggiunge al manifest un'impronta del file, così i download danneggiati vengono riconosciuti. Consigliato.
Barra di avanzamento e riga di statoMostrano il calcolo del checksum e il risultato.
Create manifest / CancelCrea e salva manifest.json; interrompe un calcolo in corso.

5. Il file manifest

Manifest Maker scrive un piccolo file di testo come questo:

{
  "version": "151126",
  "image": "solaria151126.img",
  "sha256": "3f5a…"
}
CampoSignificato
versionEtichetta mostrata all'utente. Facoltativo.
imageNome dell'immagine nella stessa cartella del manifest. Obbligatorio. Si può anche modificare a mano con un URL completo (https://…) se l'immagine si trova in un'altra cartella o su un altro server.
sha256Checksum del file immagine esattamente come caricato. Facoltativo; se presente, Raspberry Flash scarta i download che non corrispondono.

Le immagini compresse (ad es. .img.xz) si scaricano più in fretta e vengono decompresse da Raspberry Flash durante la scrittura. Il checksum è quello del file compresso: basta selezionare il file che caricate.

6. Controllare la pubblicazione

  1. Aprite nel browser l'indirizzo base seguito da manifest.json (ad es. https://drive.example.com/manifest.json): dovreste vedere il nuovo contenuto. Se vedete ancora quello vecchio, il browser o il server potrebbero averlo in cache: ricaricate dopo qualche istante.
  2. Avviate Raspberry Flash con quell'indirizzo base e premete Flash: il registro mostra Available version: … con il nuovo nome, seguito da Downloading ….

7. Risoluzione dei problemi

Messaggio / problemaCausa e soluzione
Please select an image file. (Manifest Maker)Non è stato scelto alcun file, oppure è stato spostato. Premete di nuovo Browse....
Raspberry Flash: Cannot read manifest.json: HTTP 404manifest.json non si trova nella cartella dell'indirizzo base, oppure ha un nome diverso (deve essere esattamente manifest.json, in minuscolo).
Raspberry Flash: manifest.json is not valid JSON / has no "image" entryIl file è stato modificato a mano in modo errato o troncato durante il caricamento. Ricreatelo con Manifest Maker.
Raspberry Flash: Download failed: HTTP 404L'immagine indicata nel manifest non è sul server, oppure il nome è diverso (attenzione a maiuscole e minuscole). Caricatela, oppure ricreate il manifest dal file effettivamente caricato.
Raspberry Flash: Downloaded image is corrupted (checksum mismatch) su tutti i PCIl manifest è stato creato da un file diverso da quello sul server, oppure il caricamento si è danneggiato (ad es. FTP in modalità testo). Ricaricate l'immagine e ricreate il manifest da quello stesso file.
I PC continuano a scrivere l'immagine vecchiaLa nuova immagine è stata caricata con un nome già usato. Rinominatela, caricatela e ricreate il manifest.

8. Domande frequenti

Come torno a un'immagine precedente?
Tenete l'immagine precedente sul server. Per tornare indietro, create con Manifest Maker un manifest per quell'immagine e caricatelo. I PC che la hanno ancora in cache non dovranno nemmeno riscaricarla.
Posso eliminare le immagini vecchie dal server?
Sì, quando non sono più indicate nel manifest. Tenere la precedente rende rapido un eventuale ritorno indietro.
Posso distribuire più prodotti dallo stesso server?
Sì: usate cartelle separate, ognuna con la propria immagine e il proprio manifest.json. Ogni cartella è un indirizzo base diverso in Raspberry Flash.
Il checksum è obbligatorio?
No, ma senza checksum un download danneggiato si scopre solo quando il Raspberry Pi non si avvia.
